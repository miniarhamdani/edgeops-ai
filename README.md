# EdgeOps AI — Edge Anomaly Detection & LLM Incident Explainability

> A distributed IoT monitoring prototype featuring local unsupervised ML anomaly detection on edge devices, automated incident aggregation in the cloud, and root-cause explanations generated by a local LLM.

**Tech Stack:** Python 3.11 · scikit-learn · FastAPI · PostgreSQL · Ollama (Llama 3.2 3B) · Streamlit · Plotly · Docker

---

## 1. Purpose & Scope

This project is an **exploratory portfolio prototype** built on **simulated sensor telemetry**. It demonstrates how to integrate edge-side unsupervised machine learning with centralized cloud services and localized LLM reasoning.

> [!IMPORTANT]
> This is **not** a production-grade or measurement-grade monitoring platform. All detection metrics, performance figures, and throughput values cited in this document are **indicative observations** from local simulation runs on synthetic data, not industrial benchmarks.

### a. Detection Model

The edge detector ([anomaly_detector.py](file:///c:/Users/MSI/.gemini/antigravity-ide/scratch/edgeops-ai/edge_node/anomaly_detector.py)) uses **Isolation Forest** from `scikit-learn`. 

* **Why Unsupervised?** In real-world edge IoT environments, anomalous failure states are rare, diverse, and rarely labeled in advance. Isolation Forest isolates anomalies by randomly selecting a feature and splitting values; outliers require fewer splits to isolate than clustered normal points.
* **Pipeline Structure:** Feature scaling (`StandardScaler`) is encapsulated directly inside a scikit-learn `Pipeline` alongside the estimator to prevent data leakage during incremental refits.

| Hyperparameter | Value | Implementation Source | Description |

| **`n_estimators`** | `100` | [anomaly_detector.py:87](file:///c:/Users/MSI/.gemini/antigravity-ide/scratch/edgeops-ai/edge_node/anomaly_detector.py#L87) | Number of isolation trees in the ensemble. |
| **`contamination`** | `0.05` | [anomaly_detector.py:59](file:///c:/Users/MSI/.gemini/antigravity-ide/scratch/edgeops-ai/edge_node/anomaly_detector.py#L59) | Expected proportion of outliers in the data set (5%). |

### b. Feature Space

Each edge node samples an **8-dimensional continuous numerical vector** on every cycle ([sensor.py:36-47](file:///c:/Users/MSI/.gemini/antigravity-ide/scratch/edgeops-ai/edge_node/sensor.py#L36-L47)):

| Index | Feature Name | Unit | Typical Normal Range | Underlying Distribution |
|---|---|---|---|---|
| `0` | `cpu_usage` | % (0–100) | 20.0 – 55.0% | Gaussian $\mathcal{N}(30 \times \text{load} + 20, 8)$, bounded $[5, 95]$ |
| `1` | `memory_usage` | % (0–100) | 40.0 – 60.0% | Gaussian $\mathcal{N}(45 + 10 \times \text{load}, 7)$, bounded $[20, 90]$ |
| `2` | `temperature` | °C | 45.0 – 65.0°C | Correlated Gaussian $\mathcal{N}(40 + 0.25 \times \text{cpu}, 3)$, bounded $[25, 85]$ |
| `3` | `network_in` | KB/s | 20.0 – 250.0 KB/s | Exponential $\text{Exp}(50 \times (1 + \text{load}))$, bounded $[0.5, 800]$ |
| `4` | `network_out` | KB/s | 10.0 – 150.0 KB/s | Exponential $\text{Exp}(30 \times (1 + \text{load}))$, bounded $[0.5, 600]$ |
| `5` | `disk_io` | MB/s | 1.0 – 25.0 MB/s | Exponential $\text{Exp}(5 + 2 \times \text{load})$, bounded $[0.1, 120]$ |
| `6` | `error_rate` | Ratio (0–1) | 0.00 – 0.03 | Beta $\text{Beta}(0.5, 50)$, bounded $[0, 0.15]$ |
| `7` | `latency_ms` | ms | 15.0 – 80.0 ms | Lognormal $\text{Lognormal}(3.5, 0.4)$, bounded $[10, 500]$ |

### c. Lifecycle Management

The model lifecycle runs autonomously on each edge agent ([anomaly_detector.py:43-115](file:///c:/Users/MSI/.gemini/antigravity-ide/scratch/edgeops-ai/edge_node/anomaly_detector.py#L43-L115)):

1. **Persistence Check on Startup:** At initialization, the agent checks if `models/<device_id>_iforest.pkl` exists. If present, it loads the serialized pipeline via `joblib.load` and marks `_is_trained = True`.
2. **Warm-up Phase:** If no model exists, the detector enters a warm-up buffering state for the first **`200` samples** (`training_samples = 200`). During warm-up, `process()` returns `None` and no alerts are emitted.
3. **Initial Training:** When the buffer reaches 200 samples, the node executes `_train(X)` on the baseline array, fits the `StandardScaler + IsolationForest` pipeline, and saves the binary artifact to `models/<device_id>_iforest.pkl`.
4. **Online Detection:** Subsequent readings are transformed and evaluated using `decision_function(X)` and `predict(X)`. Detections where `prediction == -1` are tagged as anomalies.
5. **Periodic Retraining:** Every **`500` readings** (`retrain_interval = 500`), the model takes the most recent 200 samples from the rolling window buffer and refits the pipeline to adapt to shifting baseline conditions.
6. **Buffer Bounding:** To prevent memory leaks on embedded hardware, if the rolling buffer exceeds $5 \times \text{training\_samples}$ (1000 items), it is sliced down to the latest $2 \times \text{training\_samples}$ (400 items).

### d. Scoring, Confidence & Severity Mapping

Raw Isolation Forest decision values from scikit-learn are transformed as follows ([anomaly_detector.py:119-135](file:///c:/Users/MSI/.gemini/antigravity-ide/scratch/edgeops-ai/edge_node/anomaly_detector.py#L119-L135)):

* **Raw Score:** $s = \text{decision\_function}(x)$. In scikit-learn, $s \ge 0$ indicates inliers, while $s < 0$ denotes outliers (typically ranging between $0.00$ down to $-0.15$).
* **Normalized Anomaly Score ($S_{\text{norm}} \in [0.0, 1.0]$):**
  $$\text{If } s < 0 \text{ (Anomaly): } \quad S_{\text{norm}} = \text{clip}\left(\frac{-s}{0.15}, \, 0.15, \, 1.0\right)$$
  $$\text{If } s \ge 0 \text{ (Normal): } \quad S_{\text{norm}} = \text{clip}\left(\max(0.0, \, 0.08 - s), \, 0.0, \, 0.15\right)$$
* **Confidence Metric ($C \in [0.50, 0.99]$):**
  $$\text{If Anomaly: } \quad C = \text{clip}\left(0.60 + 0.38 \times S_{\text{norm}}, \, 0.60, \, 0.99\right)$$
  $$\text{If Normal: } \quad C = \text{clip}\left(0.70 + \min\left(\frac{s}{0.15}, 0.28\right), \, 0.70, \, 0.99\right)$$

#### Severity Classification & Incident Aggregation
In the cloud backend ([incident_handler.py:106-114](file:///c:/Users/MSI/.gemini/antigravity-ide/scratch/edgeops-ai/cloud_backend/incident_handler.py#L106-L114)), normalized scores are categorized into four discrete tiers:

* **`Low`**: $S_{\text{norm}} < 0.35$
* **`Medium`**: $0.35 \le S_{\text{norm}} < 0.55$
* **`High`**: $0.55 \le S_{\text{norm}} < 0.75$
* **`Critical`**: $S_{\text{norm}} \ge 0.75$

**Incident Aggregation Rule:** Repeated events from the same `device_id` within a **5-minute sliding window** (`INCIDENT_GROUP_WINDOW_MINUTES = 5`) are merged into a single incident. The incident maintains a running average score, tracks the peak score, and escalates its overall severity if a higher-severity event arrives ([incident_handler.py:59-77](file:///c:/Users/MSI/.gemini/antigravity-ide/scratch/edgeops-ai/cloud_backend/incident_handler.py#L59-L77)).

### e. Synthetic Data & Fault Injection

The telemetry generator ([sensor.py:66-159](file:///c:/Users/MSI/.gemini/antigravity-ide/scratch/edgeops-ai/edge_node/sensor.py#L66-L159)) simulates diurnal variations and injects 4 distinct failure signatures with a configurable probability (`anomaly_probability = 0.05` default):

$$\text{Diurnal Load Factor: } \quad \text{load} = 0.5 + 0.3 \cdot \sin\left(\frac{\pi \cdot \max(0, \text{hour} - 6)}{12}\right), \quad \text{where } \text{hour} = \left(\frac{\text{step}}{12}\right) \pmod{24}$$

| Anomaly Pattern | Injection Mechanism & Affected Metrics | Simulated Real-World Incident |
|---|---|---|
| **`SPIKE`** | $\text{cpu} \leftarrow \text{cpu} + \mathcal{U}(40, 65)$<br>$\text{temp} \leftarrow \text{temp} + \mathcal{U}(20, 40)$<br>$\text{error\_rate} \leftarrow \text{error\_rate} + \mathcal{U}(0.3, 0.8)$<br>$\text{latency} \leftarrow \text{latency} \times \mathcal{U}(3, 10)$ | Runaway process, thread pool exhaustion, micro-burst workload. |
| **`DROP`** | $\text{net\_in} \leftarrow \mathcal{U}(0.01, 1.0)\text{ KB/s}$<br>$\text{net\_out} \leftarrow \mathcal{U}(0.01, 0.5)\text{ KB/s}$<br>$\text{disk\_io} \leftarrow \mathcal{U}(0.01, 0.3)\text{ MB/s}$ | Network interface flapping, gateway disconnection, cellular backhaul failure. |
| **`DRIFT`** | Active for $\mathcal{U}(5, 20)$ consecutive cycles:<br>$\text{factor} = 1 + (\text{duration} / 20) \times 0.6$<br>$\text{mem} \leftarrow \text{mem} \times \text{factor}$<br>$\text{temp} \leftarrow \text{temp} \times (1 + \text{factor} \times 0.1)$ | Gradual memory leak, heatsink dust accumulation, thermal runaway. |
| **`FREEZE`** | Freezes all 8 metrics to constant values for $\mathcal{U}(3, 8)$ consecutive cycles. | Sensor bus stall, I2C/SPI communication lockup, frozen telemetry daemon. |

### a. Model & Prompt Structure

When an anomaly event is ingested, the cloud service invokes **Llama 3.2 3B** via Ollama ([llm_service.py:18-97](file:///c:/Users/MSI/.gemini/antigravity-ide/scratch/edgeops-ai/cloud_backend/llm_service.py#L18-L97)):

* **Endpoint & Runtime:** `http://localhost:11434` (`OLLAMA_MODEL = llama3.2`).
* **Generation Settings:** `temperature = 0.3`, `num_predict = 512`.
* **Prompt Construction:** Metrics exceeding baseline thresholds ($\text{cpu} > 75\%$, $\text{mem} > 75\%$, $\text{temp} > 70^\circ\text{C}$, $\text{error} > 5\%$, $\text{latency} > 150\text{ms}$, $\text{net} < 1\text{ KB/s}$) are explicitly tagged under `Key Outliers Identified`.

```text
ANOMALY PROFILE:
- Classified Pattern: {ANOMALY_TYPE}

3. Provide a concrete technical hypothesis (e.g., thread starvation, memory leak accumulation, thermal throttling).
4. Provide 2-3 precise, actionable remediation commands or steps.

Respond with a JSON object only (no markdown wrapping, no comments):
{
  "explanation": "<concise 2-3 sentence technical analysis citing the exact anomalous numbers>",
  "recommended_action": "<concrete diagnostic and mitigation steps for an edge node>",

}
```

The service enforces a strict output contract ([llm_service.py:124-140](file:///c:/Users/MSI/.gemini/antigravity-ide/scratch/edgeops-ai/cloud_backend/llm_service.py#L124-L140)):

## 5. Known Limitations

1. **Static Contamination Rate:** Isolation Forest relies on a fixed `contamination = 0.05` parameter. If the true anomaly rate in production deviates from 5%, the model will either produce excess false positives or miss subtle anomalies.
2. **Trend Drift Absorption:** Because periodic retraining fits on the most recent 200 samples, slow monotonic drifts (e.g., progressive memory leaks) risk being absorbed into the model baseline.
3. **Heuristic Score Calibration:** The transformation from raw `decision_function` values to $[0, 1]$ relies on a fixed linear scaling factor (`-score / 0.15`), which is an empirical approximation rather than a mathematically calibrated posterior probability.
4. **Local LLM Repetitiveness:** Small 3B parameter models have constrained context windows and may generate repetitive phrasing if sensor telemetry contains subtle, multi-metric variance rather than extreme spikes.
5. **No Edge Offline Spool:** If the cloud backend is unreachable, edge nodes log connection errors but do not buffer events to a local persistent queue (e.g., SQLite WAL or local disk buffer).
6. **Simplified Backend Auth & Migrations:** API authentication uses a shared static header (`X-API-Key`); database schemas are created via `models.Base.metadata.create_all()` on startup without Alembic migration versioning.

```bash

git clone <repo-url>
```
